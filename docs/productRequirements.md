# Product requirements

## Current application

A Georgian restaurant browsing website with English and Russian translations, branch selection, product details, a browser cart, and validated local checkout.

| Route                | Behavior                                                     |
| -------------------- | ------------------------------------------------------------ |
| `/[locale]`          | Complete menu with category, branch, and search filters      |
| `/[locale]/about`    | Selected branch gallery, opening hours, and contact sections |
| `/[locale]/cart`     | Saved selections, quantities, serving choices, and totals    |
| `/[locale]/checkout` | Local contact validation and completion                      |
| `/[locale]/login`    | Informational page                                           |
| `/[locale]/terms`    | Legal article with section navigation                        |
| `/[locale]/privacy`  | Privacy article with section navigation                      |

## Installed application

Installed PWA presentation uses the supplied logo, a black and white app icon, localized name and description, and a launch URL matching the installation language. Standalone display requests a window without the browser address bar on supported platforms. A white or dark window bar follows site appearance. Include 192 and 512 pixel install icons, a maskable icon with safe logo padding, and a 180 pixel Apple home screen icon. All supported locale routes remain within one app scope. Ordinary browser tabs keep browser controlled navigation. Firefox Windows web apps retain browser owned controls and a read only address bar. Use a browser supporting standalone PWA presentation, such as Chrome or Edge, for a window without that toolbar. Installation presentation does not imply offline ordering or background push support.

## Menu and product behavior

Render all matching dishes in the server response. Filter the supplied catalog in the browser, without infinite scrolling. Search matches titles across supported languages. URL state preserves branch, category, search, and selected product. Display category counts beside headings.

Selecting a branch closes the location sheet immediately. On the menu, update the branch URL, header label, and filtered catalog together without waiting for a server request. Preserve language, category, and search, and reset the pagination cursor. On the About page, switch the branch and show gallery skeletons while its server data loads.

Product details support descriptions, quantity, serving selection, sharing, and full screen image viewing. Share controls are hidden while SHOW_SHARE_BUTTON is false. When enabled, they use a common tooltip delay. Product details use a 90dvh bottom drawer on mobile and a centered dialog on desktop. Opening details from a cart or removal toast preserves the cart sheet.

### Planned order confirmation and delivery

1. The customer submits an order for manual review in the admin area or a future staff area. The choice of staff surface remains open.
2. A staff member accepts or declines. A decline notifies the customer without charging them. Staff may attach a customer facing reason. Suggested reasons include an unavailable dish or a busy kitchen, with final reason choices still to be designed.
3. After acceptance, obtain a Wolt Drive delivery quote and update the customer view with the authoritative food total, delivery fee, and final payable amount. Notify the customer that confirmation is required and ask them to reconfirm the updated total before payment.
4. The customer pays the displayed final amount. Only after successful payment does courier dispatch begin and the restaurant start cooking.
5. The customer receives a Wolt Drive tracking link.

This sequence is an approved product direction and is presented as planned behavior. Live submission, staff review, notifications, payment, delivery quotes, dispatch, and tracking remain unimplemented. Notification channels and payment provider selection require product decisions. Validate Wolt Drive quote, dispatch, and tracking contracts before implementation.

# Architecture

## Stack

Next.js App Router, React, strict TypeScript, Tailwind CSS, shadcn and Base UI primitives, next-intl, Zod, React Hook Form, and Zustand.

## Ownership

| Directory             | Responsibility                                          |
| --------------------- | ------------------------------------------------------- |
| `app/[locale]`        | Localized pages, layout, metadata, and route boundaries |
| `app/api`             | Public read endpoints                                   |
| `components/features` | Menu, branch, cart, and checkout UI                     |
| `components/shared`   | Header, footer, theme, images, and legal content        |
| `components/ui`       | Generated shadcn primitives                             |
| `hooks`               | Client behavior and store selectors                     |
| `lib`                 | Queries, stores, and focused utilities                  |
| `schemas`             | Input, response, and storage validation                 |
| `types`               | Shared domain contracts                                 |
| `constants`           | Client safe constants and ECategory and EPlace enums    |
| `messages`, `i18n`    | Translations and locale navigation                      |
| `tests`               | Feature grouped behavior and regression tests           |

Tests are grouped under cart, checkout, menu, navigation, places, pwa, sharing, i18n, and theme. The test command discovers nested test files. Keep behavior and regression coverage with its owning feature, and avoid duplicate checks or assertions tied only to temporary fixture content.

## Rendering and state

The locale layout suppresses hydration warnings on the body element because browser extensions can add attributes before React hydrates. Page components retain hydration checks.

Server Components compose routes and fetch the complete menu and branch gallery. Serializable data reaches interactive components. Menu filters live in URL parameters and operate on the supplied catalog without infinite scrolling. The matching dishes render in the server response for direct category and search links.

Branch selection on the menu uses the same native history updates as other menu filters. The URL remains the source of truth for the header and catalog, with no server navigation needed for data already supplied. About branch navigation uses a branch keyed Suspense boundary so the new URL can commit with a gallery skeleton while server data loads.

The locale layout rejects unsupported locales without explicitly opting into instant navigation validation. Pages retain framework default validation, while the catch all 404 page opts out. The shared food placeholder uses eager loading consistently because it also appears above the fold. Other card images follow their individual loading policy. The header, error page brand, and adaptive SVG application icon use the supplied brand artwork. Error recovery uses browser history with a localized menu fallback when history is unavailable. The React logo inherits currentColor, including dark and light appearance. Primary add and checkout actions and branch card footers share a full coverage SVG logo pattern with larger marks in staggered diamond rows, animated spacing, and reduced motion support.

Zustand owns cart selections, totals, sheet visibility, and appearance. A symbol keyed property on the browser window preserves the cart store across development module reloads. useCart resolves that shared store directly instead of retaining an older store instance in hook state. Server rendering still receives isolated empty snapshots. Cart and theme storage restore after mounting. Product detail submissions read the latest store snapshot, commit absolute serving quantities, and select the editable order tab even when history was previously shown. getProductOrderAction chooses add for new servings, update for saved servings even when unchanged, and remove at zero. Product details show a localized unit price below the title. Item toasts distinguish added, updated, and removed selections. Cart lines, appearance, and the notification reminder dismissal preference persist. Contact fields and completion state remain local to checkout.

CartDrawerContent composes shadcn tabs for the editable cart and pending orders. submitDemoOrder snapshots the cart into session memory pending orders before clearing persisted cart selections. Snapshots keep read only items, quantities, serving choices, and food totals independent of subsequent cart edits. They retain no contact fields and are excluded from localStorage and initial server snapshots. getOrderGroups places courier orders on the way first, followed by customer confirmation, active pending orders, and terminal history, each newest first. Declined order details replace delivery cost, estimated arrival, and total values with a localized destructive status message. Confirmed customer totals stay in pending until a distinct courier state exists. PendingOrders composes these headed groups without a preview footer. OrderFlow explains the planned sequence on checkout only. CartSummary identifies delivery as an additional fee. No server order mutation or external call exists. Future trusted server operations must own staff decisions, delivery quotes, final totals, payment confirmation, courier dispatch, and customer tracking. Staff area placement and notification channels remain undecided.

One URL driven product dialog supports menu, cart, and toast entry points. It appears as a 90dvh bottom drawer below 640 pixels and a centered dialog on larger screens. Opening it preserves an existing cart sheet. Shared image dialogs handle full screen viewing. Layout composition stays in route layouts.

## Internationalization and styling

Each locale exposes a public manifest.webmanifest Route Handler with translated app identity and a locale launch URL. All manifests share a root app id and scope so switching languages or opening checkout remains inside the installed standalone window. Layout metadata links that manifest, declares the Apple web app and touch icon, and supplies a white light theme color. ThemeProvider synchronizes that color with saved and manually selected appearance. The app icon uses the supplied logo in white on zinc black with mask safe padding. scripts/generatePwaIcons.ts exports PNG installation assets and the favicon from the SVG using the existing Sharp dependency. The manifest configures installed presentation only. Browser and operating system support determine native chrome, and normal tabs retain their address bar. Firefox Windows web apps also retain a read only address bar and browser controls. Chrome and Edge standalone installs provide the toolbar free presentation. No offline or customer data cache is introduced.

The order drawer uses the shadcn tabs pill variant and one Base UI indicator, with rounded-xl on the track and rounded-lg on the controls and indicator. Its title and close control share one top padded row. Base UI measures the active tab and supplies position and size variables. CSS transitions move the shared background between tabs without replacing it. Reduced motion disables the transition. Tab labels retain their keyboard focus and activation behavior.

CartRuntime supplies the placeholder image URL when hydrating the browser store. createDemoOrders creates dated staff pending, customer confirmation, declined, and delivered fixtures from validated catalog seeds. Initial server state stays empty. createOrderActions owns drawer selection, collapse, staff acceptance simulation, and customer reconfirmation. openOrder always expands an exact record, while toggleOrder can collapse it. getSortedOrders orders records by creation time without mutating storage. getActiveOrders includes onTheWay courier records and excludes terminal states from the notice carousel. Courier notices use a truck icon and their fixed estimated arrival. Courier notices remain visible alongside the highest priority waiting records. Notes use a shared optional schema and stay in session snapshots without contact fields. Pending totals exclude delivery until the confirmation required state.

getImportantOrders includes all courier deliveries first, followed by the highest priority waiting status. Customer confirmation requests hide staff pending records, which take priority over confirmed records. Equal priority records retain newest first order. getOrderNoticeLayout reserves measured space beside open desktop sidebars and for the notification permission card. useOrderNoticeLayout observes open sheet state and reads layout widths before transforms finish. Right sidebars move the dock to their left. Left sidebars reduce available row capacity. Language, location, and order sheets share the dock motion curve and duration. Full width mobile sidebars hide the dock until they close. On desktop that card sits to the left of the confirmation notices whenever both fit. Expanded floating cards share a 280 by 104 pixel frame. Each can animate into its own 44 pixel icon at the bottom edge and expand again. CollapsibleNoticeFrame freezes an expanded canvas and scales it toward the bottom right inside a shrinking clipped frame, preventing content reflow or overflow behind the icon. useOrderNoticePresentation keeps collapse state by order identity and status so changed statuses appear expanded. Collapsing or expanding an order notice on mobile applies the same state to all currently displayed order notices, including offscreen slides. Collapsed slides use their icon width and form a compact row whenever they fit, without retaining full card slots. Desktop notices retain independent collapse controls. Layout calculations include actual collapsed widths and preserve focus when row and carousel modes change. Short permission copy keeps its frame consistent, while blocked retry instructions open in a separate shadcn dialog above the dock. The remaining width determines whether order cards form a row or carousel. Narrow layouts stack permission controls above the notices. OrderNoticeCarousel owns both row and carousel presentations, disabling Embla when all cards fit. Card identity stays mounted across mode changes so collapse animations remain continuous. Courier cards appear first, with newest first ordering within each status. Inline cards reverse this sequence so the first notice sits at the right edge. Overflow uses the Embla controls and a combined position and confirmation label below the active card on mobile and above it on desktop. useOrderNoticeLayout subscribes to viewport and product drawer DOM changes with useSyncExternalStore.

Confirmation banners and count badges use black backgrounds and white text in light appearance, with white backgrounds and black text in dark appearance. Outer cards retain their subtle theme border. Floating cards, collapsed controls, and pending order cards share rounded-lg. Inner banners, status badges, confirmation panels, and product images use rounded-md, with rounded-sm for compact controls. All collapsed icons use a borderless black surface and white glyphs. Permission reminders use a crossed out bell. Confirmation bells periodically ring in cards, collapsed controls, and status badges, respecting reduced motion. Chevron collapse controls occupy a separate light area beside the black banner. Confirmation headings stay on one line. Floating reminder actions share one row, and declined copy explains that confirmation updates still appear in the page. Compact notices show status, arrival, and total without a visible order number. The palette and a shared 300 millisecond drawer motion duration and curve live in app/globals.css. Newly mounted notices and item toasts slide upward with reduced motion support. Opaque hover backgrounds preserve the card surface. A 12 pixel gap separates notice cards and transient toasts, with matching desktop and mobile bottom offsets. The order sheet slides its full width on desktop and its full height on mobile. Both mobile drawers take 90dvh. On desktop the floating notice animates beside the open order sheet. On mobile the order sheet hides it. A black dot beside the pending orders tab indicates customer confirmation is needed. Mobile product drawers hide the entire notification dock until closed.

Overflow order notices support touch swipes and mouse dragging, with a twelve pixel gap between slides. Embla suppresses clicks after a drag while ordinary presses still open order details. Offscreen buttons leave the tab order without native inert slides. Selecting a notice closes any product dialog before selecting order details, preserving menu filters. useNotificationDock reserves actual panel height below desktop and normal mobile toasts. PendingOrderLine uses 80 pixel thumbnails and plain separators, with image hover zoom and no row background or rounded hover border.

OrderArrival shares a localized arrival clock between the notice and details. The order record stores an absolute estimatedArrivalAt deadline, assigned when a sample quote is confirmed. useCurrentTime updates its presentation each second. getOrderArrivalState returns Soon below one minute remaining, including elapsed estimates, and keeps unknown deadlines explicit. Repeated staff acceptance or customer confirmation cannot restart the deadline. CtaPattern explicitly fills buttons to avoid icon sizing rules.

useDemoOrderConfirmation owns a cancellable ten second fixture timer. useOrderAlerts detects staff pending to confirmation required transitions once, updates the persistent status card without a duplicate toast, optionally plays Web Audio unlocked by interaction, and attempts an already permitted browser notification. Checkout completion presents OrderNotificationPermission. useNotificationPermission reads browser permission and a page session dismissal attribute through useSyncExternalStore, keeping the checkout prompt and floating controls synchronized. Allow and Ask again call the native API directly from user interaction. Denial remains visible, and blocked retries mount NotificationBrowserHelp with numbered instructions for Firefox, Chrome, Edge, or Safari, without a divider or external instruction link. NotificationPermissionArrow portals a decorative pointer above the help dialog toward the browser controls at the viewport edge, with a callout naming the first step. Its path updates on dialog and viewport resizing. Native browser chrome cannot be measured or drawn into by page code. getNotificationBrowser performs local user agent matching only for this guidance and falls back to generic instructions for unknown brands. Browser data is not persisted or transmitted. The declined reminder includes Do not show again, stored as a browser preference with an in memory fallback when storage is blocked. This hides the reminder without changing native permission or order status. Unsupported contexts keep ordering available. Constructor failures are nonblocking. There is no background Web Push or socket connection. These local effects can later consume authenticated server events without trusting client statuses for payment.

Desktop checkout uses a centered compact grid with contact and total, Your order, and explanation columns. The form has tighter spacing, and document scrolling owns all checkout content without nested scrollbars or sticky columns. Tablet keeps the explanation below two columns and mobile stacks sections. CartItems, CartLine, and their loading state accept the compact checkout presentation. The shared textarea and order note schema provide bounded optional notes. Order headers use a full bleed background with square lower corners above animated details. Tab selection now uses an ease in out curve that starts and finishes more slowly.

Manual theme changes use transitionTheme to apply one temporary 200 millisecond transition policy to all surfaces, then restore normal component transitions. Reduced motion switches immediately. Locale prefixed routes support ka, en, and ru. All UI copy uses translation keys. Georgian uses Noto Sans Georgian, while English and Russian use Inter. Palette tokens live in app/globals.css. Feature styles live under app/styles. Category filters are always expanded. On wide desktops category arrows are centered in the gutter between the carousel and viewport edge. Mobile category arrows and their hidden counts sit closer to the viewport sides with an eight pixel inset. Header flag, theme, and order controls use equal eight pixel gaps on mobile and twelve pixel gaps on larger screens, without a flag margin. Category cards use equal top and side padding, full width square images, and room for two label lines. The all dishes category uses one image with the same hover zoom as other categories. Loading placeholders match the card dimensions. About body content is capped at 1200 pixels while its gallery remains full width. Components use responsive Tailwind classes and shared shadcn primitives.

The dark menu panel token uses Tailwind zinc 900 to match the shadcn zinc palette. Category filters and the footer use it without transparency in dark mode. The checkout main and order grid fill the existing layout space without imposing an additional minimum page height. The form and explanation stay in normal document flow.
